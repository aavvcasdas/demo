# 67–72 人生副本复盘：模型失误、skill 缺口与 v3 修复

日期：2026-09-17

## 结论先行

67–72 的问题不是单纯「模型变笨」，也不是单纯「skill 写得太多」。两者是共同失效：

- **模型执行层**把拆文的表面结构和沉沦模板当成了新题材事实：会把金额升级、玄学预感、社死反杀、结果前置一起搬进来；写完没有重新算日期、票数和规则。
- **skill 设计层**给了模型错误的奖励信号：更重视八拍、300行、呼应数、关键词和「社死台词」，却没有一个统一的硬事实账、因果/状态账、对象称呼账；对白门禁还只按带「说」的行计数。
- **验收层**因此会出现「格式 PASS、正文仍然逻辑错」：旧门禁曾让旧版72的 `DRAFT: PASS`，但正文同时写了双色球结构、2元变10元、七年与八年、号码有感觉和三等奖是信号。

本次已将规则性修复写入：

- `skills/story-short-write/references/genre-styles/人生副本实录.md`：v3，事实锁、彩票专用账、线性首屏、因果状态台账、低对白和按题材选择高潮。
- `skills/story-short-write/references/genre-styles/人生副本_通用骨架.md`：从「300行硬目标」改成对象图 + 因果图 + 可选短行节奏。
- `skills/story-short-write/SKILL.md`：修正不存在的「§十五」引用，要求人生副本同时读取通用骨架并跑 `fuben_run.py`。
- `skills/fuben-review/SKILL.md`：v2，三方审核先查事实、日期、数字、知情面和一遍读懂，再查拆书机制。
- `scripts/fuben_consistency.py`：新增事实锁、规则混用、金额/频率漂移、玄学结果、日期/票数和状态台账检查。
- `scripts/fuben_loop.py`、`scripts/fuben_lint.py`、`scripts/fuben_run.py`：改为事实优先；对白按功能单位而不是字符「说」计数，AI advisory 不再逼短行稿机械注水。

旧版72没有覆盖；隔离新稿仍在 `作品/72_每天买一张彩票的人_重生成基线/`。

## 一、67–72 的共同症状与证据

### 1. 67：结果前置后直接倒回童年，读者没有时间路标

旧版67开头先给出「大三用四十秒甩她」「三年后面试官是她」，随后马上进入「初二」和高中，再回到大三五月。这个结构可以作为明确的结果前置，但原稿没有先告诉普通观众「现在先看结果，下面回到你第一次学会‘不合适’的那一年」。

问题不是不能倒叙，而是倒叙没有承担信息功能：读者需要自己推算「初二 → 大三 → 三年后」。skill v2 只检查闪回行数和金句位置，没有检查首屏路标。

### 2. 68、69：对话是主要信息搬运带，人物问答挤掉了动作和状态

旧门禁运行结果：

| 作品 | 旧 `fuben_loop` 说话行 | 旧门禁结果 | 原因 |
|---|---:|---|---|
| 68 | 61 / 约12% | FAIL | 家庭分配、记账、室友反应都用来回问答说明 |
| 69 | 57 / 约11% | FAIL | 大一到毕业反复让同一个人说话，主角靠追问等回应 |
| 70 | 11 / 约2% | PASS | 低对白，但仍把「证据档案/括号」当作抽象解释器 |
| 71 | 旧规则只报3行 | PASS | 实际有大量「主管讲……」「你回……」式话术，旧正则漏计 |
| 72 | 旧规则报12行 / 3% | PASS | 形式恰好压线，但事实与规则已经漂移 |

68的原文从「你说 妈 生活费」到「她说 你弟真幸福」连续累积问答；69从「你说 七点」到「他说 作业」也形成对话链。它们并非每句都坏，但同一类信息被问了很多遍，剧情状态没有同步变化。

根因是「对白≤12行/≤3%」只数直引行，不数转述式对白，也不问对白删掉后是否仍推动动作。v3 改成：默认全篇≤8个功能单位、≤4%，一场最多一问一答；保留改变行动/关系/规则认知的句子。

### 3. 72：彩票事实和数字账发生了多处硬冲突

旧版72正文的可定位证据：

- L3–L6：`守了7年的一组号`、`1000万`、`最后坐回同一张凳`、`中间只隔了两年`，结果前置但没有说明时间口径。
- L9：从 `二零一七年十二月` 开始；L112：`二零二四年三月` 中奖。起点到此只有约六年三个月，不是正文开头的七年。
- L62：`两块变成十块`；L76–L77：`七年`、`每天十块`。这直接违反「每天一张/单注2元」的稳定规则。
- L264–L291：中奖后出现一百倍、两百倍、五百倍、一千块、三等奖是信号、再买到过年；这是从固定守号跳成了倍投升级。
- L112附近：正文使用`六个红球、一个蓝球`，实际写的是双色球结构；新基线选择福彩3D后，必须使用000–999三位单式票，不能混玩法。
- L415–L416：`从二零一七年十二月……八年里`，而设定与前文多次写七年。
- L65附近：`你也觉得这组号有感觉`；L291附近：`三等奖是信号`；这把随机结果写成了预感/信号。

旧版设定卡甚至把这些冲突预先写进了模板：一边说「守一组号七年、每天两块」，一边又规定「2万→4万→8万」的倍投链。这不是正文某一处润色能解决的，而是事实锁不存在导致的设计污染。

### 4. 67–72 不是同样差，不能用一个反杀模板概括

- 71 的「按字面办事」主线相对完整，主管话术 → 本子记录 → 全组学会追问 → 守则成形，说明模型在单规则、单场域题材上能保持因果。
- 70 的物件（备忘录、伞、香菜）和「三条证据」有回收，主要风险是开头结果前置和抽象标签需要更直白。
- 67 的面试对位有动作回收，但首屏倒叙和面试现场的对话功能需要更清楚。
- 68、69 的主要退化是对白和重复场景；68还曾被当前 lint 报23处她/他不清，69曾报81处，说明人物窗口不够明确。
- 72 是事实底座最严重的案例：不是「对白太多」为主，而是彩票规则、日期、金额周期和结果因果同时失锁。

所以修复不能只是统一删对白；必须按题材先锁规则，再决定是否需要对手、社死或反杀。

## 二、共同根因：模型与 skill 各自负责什么

### A. 模型执行失误

1. **供体模板污染**：看到 `04/21` 的数字坠落、回本三部曲和系统拟人，就把它当成沉沦题默认剧情；没有判断「固定低剂量习惯」与「金额升级成瘾」是两个分支。
2. **局部续写代替全局对账**：生成「七年」时没有重新计算2017到2024、2017到2025的真实跨度，也没有检查闰日与第几张票。
3. **把戏剧感觉当彩票机制**：用「有感觉」「快了」「信号」制造悬念，违反随机结果边界。
4. **短行误解**：把短行理解成每行一个碎片，连续写年份、身体反应和问答，导致流水账；短行没有和状态变化绑定。
5. **代词省略过度**：在多人物场景沿用最近一次的「她/他」，模型以为上下文足够，普通观众却要回看前文。

### B. skill 设计/验收缺口

1. **L0 不是事实锁**：原规则要求L0有时间、价格、生态和来源，却没有一个字段规定「本篇最终只能采用哪个玩法、频率、单位和号码周期」。
2. **沉沦分支写成了默认升级**：旧包明确给出「2元→2万→4万→8万」和回本三部曲；它没有写「只有用户原案明确要求金额升级时才可用」。
3. **固定八拍强制制造高潮**：第五拍社死、第六拍对照审判、结尾对手动作对人物题有用，对福彩3D规则题会逼出老板娘/陈哲的假反派。
4. **结构指标替代语义验收**：主线关键词、呼应对数、300行、每30行感官都能绿，但不能证明金额、日期和因果正确。
5. **对白指标失真**：旧代码只在特定句式和引号中计数；「主管开口」「他说」「你回」的组合可以漏计，转述式对话也不等于旁白。
6. **指代检查失真**：只看窗口内的同性别候选，没有按最近明确身份和动作主语解析；于是有的稿子漏报，有的稿子要求机械重复姓名。
7. **倒叙合法性没有硬门**：旧规则允许一拍结果前置，但没有要求立即给时间路标、回到哪一年和回到何处。
8. **审核流程没有真正阻断**：旧包把 `fuben-review` 放在后面，但没有在事实/状态账缺失时让生成停下；旧稿可以先写、后用形式审核找补。
9. **文档自身漂移**：主 `SKILL.md` 曾要求按人生副本包的「§十五」执行，而该包只有到§13；v3已改成明确的 §0→§5，并增加机械串联命令。

### 归因判断

因此答案是：**模型错了，但 skill 让这种错很容易发生、很难被拦截。** 如果只有模型问题，统一的事实锁和状态台账会在写作前/写作后挡住；如果只有 skill 问题，模型也不应凭空把「每天10元、三等奖信号」写进与用户要求冲突的稿子。两层都要改。

## 三、外部检索与拆文方法取舍

### 1. `拆文库`案例

- `01_无辣不欢的一生`提供的是「一个小动作贯穿多年、具体物件反复出现、奖赏/代价逐渐改变」的线性骨架。
- `04_中10亿彩票的人生`适合借「结果反写、物件双义、账户数字下降」，但它的千万中奖和后续重仓不能移植到福彩3D固定2元题。
- `21_大学生意外接触PG电子游戏`适合借「系统规则先于情绪、余额账、沉沦动作递进」，不能把网赌/倍投升级当成所有彩票故事的必然结构。

### 2. GitHub/公开方法

- `Mr-funny/hbg-life-simulation` 的公开工程说明把「冻结原始文案、锁定人物锚点、故事数据与分镜构建分离、按真实语音时间做最终QA」作为流程重点。v3对应吸收为事实锁、对象台账、状态台账和最后机械/人工复核；来源：https://github.com/Mr-funny/hbg-life-simulation
- `1-SKILL/jiaoben` 将 hook、平台节奏和自检拆成阶段，说明短视频脚本需要结构化验收；其流量效果是项目自称，v3不把「完播率翻倍」当规则；来源：https://github.com/1-SKILL/jiaoben
- 知乎的「人生副本」拆解强调第二人称、物证包和日常循环；v3保留「物证 + 循环」，但把「不删减强制模板」改成事实/因果优先；来源：https://zhuanlan.zhihu.com/p/2053820536841573794
- 新榜对「剧本人生」的报道显示，真实普通人的具体工作和生活经历比泛化猎奇更容易引起共鸣；v3因此把「一遍读懂、具体称呼、客观动作」放在抽象金句前；来源：https://news.qq.com/rain/a/20260826A0DBMC00?id=20260826A0DBMC00&path=a&app=qqnews

外部资料只提供流程和观察，不覆盖用户给出的硬事实；彩票玩法事实仍需使用选定的规则来源和正文内的事实锁。

## 四、已落地的 v3 验证

### 1. 新基线事实选择

新稿已经锁定：福彩3D、每天一张新的2元单式票、固定417、官方结果核对、中奖1040元。日期口径改为：2019-09-17第一张，2026-09-16第2557张，含2020和2024两个闰日；2026-09-17为满七年后的第二天，停止购买。购票成本为2557×2=5114元。

### 2. 门禁结果

对 `作品/72_每天买一张彩票的人_重生成基线/` 运行：

```text
[L1 design] PASS
[L1.5 facts] PASS
[L2 draft] PASS
[L2.5 review] PASS
[L2.6 lint] PASS
[AI-patterns] PASS（仅 advisory：短行过密提示；没有 blocking）
```

这个 PASS 只说明机械事实、结构和可读性门禁通过，不等于替代人工 `fuben-review`；短行体确实较密，后续仍可人工听读，但不能为了消除 advisory 机械加入空对白和流水动作。

对旧版72运行新 `facts` 门禁会至少阻断：

```text
NO_FACT_LOCK      没有可执行事实锁
NO_STATE_LEDGER   没有因果/状态台账
DURATION_CONFLICT 设定七年、正文写八年
```

旧版正文中已经记录的玩法混用、2元→10元、预感和倍投，也在人工 Phase 1 明确列为 S1；它们不能靠旧稿的呼应表或短行格式放行。

### 3. 后续使用规则

- 新题先建事实锁，不直接从旧作品续写。
- 规则/习惯题默认线性，不强制结果前置、社死、反杀和系统人格。
- 对白超过功能预算，先删问答再考虑补动作；不使用「你说/他说」堆节拍。
- 每次外部反馈若在两篇以上复现，先回写 skill 和脚本，再改新稿。
- 旧67–72作为反面样本保留，不用「全部重润色」掩盖是流程问题。
