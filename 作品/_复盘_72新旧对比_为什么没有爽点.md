# 72 新旧对比：为什么「新 72」一点不紧凑、一个爽点都没有

日期：2026-09-17 ｜ 对象：`作品/72_每天买一张彩票的人/`（旧）、`作品/72_每天买一张彩票的人_重生成基线/`（新）、`作品/72_每天买一张彩票的人_爽点紧凑版/`（本次重做）

---

## 结论先行

1. **新 72 不是「写得差」，是 v3 的规则里根本没有「爽点」这一项。** v3 的优先级写的是「用户硬事实 > 事实锁 > 线性因果与可读性 > 选定拆文的机制 > 八拍/短行形式」，机制排在可读性之后，情绪与爽点一次都没出现；而 `fuben_loop.py design` 又把「八拍表≥8 行」「≥6 拍有推进/受阻/揭示/改变/停止/核对」写成硬门。于是模型被两把尺子夹住：**事实不许错、每拍必须有状态变化**，从来没人要求它「在 22% 之前给观众一个 +5」。结果就是 2510 字全部合规、全程 0 到 -3、唯一正向事件落在 90% 且只有 1040 元。
2. **「不紧凑」可以被量化：单位字数里的情绪翻转次数。** 39 篇拆文库样本的节点密度是 5.1–16.7 个/千字；新 72 是 **0.4 个/千字**（2510 字里 1 个正向事件）。旧 72 爽点不少，但第一爽点在 31%、爽点群挤在 31%–44%，前面三分之一是纯编年、后面 37% 是单向下坠——**两稿都不紧凑，只是病因不同：旧稿爽点来得晚、来得挤，新稿爽点根本没来。**
3. **拆文库的爽点是可以照抄的**，而且我在 v4 里把 14 条机制写成了「爽点池」（数字并置、他人身体反应做刻度、围观对位、跪—给—晒—删、单物件双义、余额跳水、打脸换手、器物/数字判词……）。照着池子改出来的 `72_爽点紧凑版`：2263 字 / 301 行，14 个情绪节点（6.2/千字）、9 个正向爽点、峰值 +8 落在 **45%**、谷底 -8，机械闸全绿。

## 二、「不紧凑」的量：情绪翻转次数

把每篇按字数切段、标情绪值（拆文库五维口径），数「符号翻转」次数：

| 篇 | 节点密度 | 翻转次数 | 峰值位置 |
|---|---:|---:|---:|
| 01 无辣不欢 | 6.9/千字 | 12 | +7 @ 21% |
| 04 中10亿 | 12.4/千字 | 6 | +7 @ 34–40% |
| 21 网赌 | 7.5/千字 | 10 | +3 @ 19%（首胜） |
| 13 死装姐 | 6.3/千字 | 9 | +5 @ 48% |
| 旧 72 | ≈7.0/千字 | 7（集中在前 44%） | +7 @ 37–41% |
| **新 72** | **0.4/千字** | **1** | **+1 @ 90%** |
| 新 72 爽点紧凑版 | 6.2/千字 | 6（前 68% 为爽点区，后 32% 结算） | +8 @ 45% |

新 72 的分段情绪流水（段号 / 字数 / 情绪值区间）：

```text
段1 321字 0        —— 买票，没中奖
段2 326字 -1 → 0   —— 陈哲翻了两张票就盖上，主角无反应
段3 362字 0 → -1   —— 搬家丢铁盒又被母亲找回（本该是 +3 的暖点，被写成「你也没有问」）
段4 369字 -1 → -2  —— 母亲住院；陈哲拿十块钱劝他加注，主角不接话
段5 384字 -1 → 0   —— 416 近号，老板娘科普「每一期都是重新摇出来的」
段6 362字 -3       —— 母亲算账：2557 张、5114 元，药单还差 340
段7 255字 +1       —— 中奖 1040 元，随即「两张纸都没有发热」
段8 131字 0        —— 停止购买
```

**段2 到段6，1803 字（72% 的篇幅）情绪值一直待在 0 到 -3 之间，没有任何一次翻转。** 这就是观众嘴里的「一点不紧凑、太慢」——不是字多，是没有情绪变化。对照 21：同一批字数里它完成了 首胜 +3 → 全能感 +3 → 拖拽 +2 → 归零 -5 → 借款 -6 → 粉碎 -8。

旧 72 的问题在同一张尺子上也看得见：**第一爽点在 31%，前三分之一全是 2017→2024 的年表**；爽点群挤在 31%–44%；49% 之后到 86% 是 37% 篇幅的单向下坠（四百一十万 → 八十块三毛），一路只有「加倍数、输掉、再借」三种动作重复。**它不慢的是字数，慢的是前 31% 没有任何兑现。**

## 三、「没有爽点」的 8 处行级证据（新 72）

| # | 位置 | 原文 | 问题 |
|---|---|---|---|
| 1 | 段2 L22–L26 | 「陈哲翻了两张 / 又把铁盒盖上 / 你没有向陈哲解释」 | 有对手、有围观，主角零反应：憋屈立了，**没有结账** |
| 2 | 段3 L29–L33 | 「母亲没有问你丢了什么 / 母亲不记得什么时候替你收走的 / 你也没有问」 | 一个天然的 +3 暖点（物件失而复得）被三句否定抹平 |
| 3 | 段4 L60–L70 | 「陈哲说每天只买两块钱 / 等到退休也等不到 / 你把最上面的票捡起来……」 | 唯一一次对抗，主角全程挨打，票被倒在桌上，读者拿不到任何代偿 |
| 4 | 段5 | 「每一期都是重新摇出来的」 | 把规则讲清了，也把戏剧性讲没了——观众要的是兑现，不是概率课 |
| 5 | 段6 | 「本月还差 340 元」 | 全篇最痛的 -3，但它没有对应任何一次曾经的高点，落差为零 |
| 6 | 段7 | 「中奖金额 1040 元」 | **全篇唯一正向事件**。七年、2557 张、5114 元，换 1040 元——数字太小，撑不起「人生副本」的兑现 |
| 7 | 段7 | 「你没有听见号码在说话 / 也没有感觉到它认出了你」 | 防玄学防过头：连人物该有的身体反应一起删了 |
| 8 | 段8 | 「铁盒里只剩一个空纸套」 | 灰收束没错，但前面没有峰值，灰得没有重量 |

对比 04 是怎么给爽点的（同题材、同「彩票」外壳）：`+6` 地铁上看见 7.95 亿余额、工牌砸在主管脸上（28%）；`+7` 全款 8600 万，售楼小姐端咖啡的手在发抖（34–40%）；`+4` 让曾经拒绝你的投资人喝整瓶茅台（59%）。**它的爽点不是靠加钱，是靠「别人在你的钱面前变了形」。**

## 四、根因：v3 的五条规则，条条都在删爽点

| v3 原文 | 它修对了什么 | 它顺手删掉了什么 |
|---|---|---|
| `0.2 冲突优先级：… > 线性因果与可读性 > 选定拆文的机制 > 八拍/短行形式` | 防止用文风掩盖事实错误 | **优先级里没有「爽点」**。机制被排在可读性之后，实际执行等于「先把因果写对，好看再说」 |
| `2.5 规则/习惯/低剂量沉沦：不得强行加入 倍投、天选、会说话的系统、社死审判` | 防 2 元变 10 元、防预感 | 连「对手、围观、兑现、称呼翻转」一起禁掉；新稿的陈哲只能笑着走 |
| `3.2 对白预算：全篇 ≤8 个功能单位、一场最多一问一答` | 防问答堆节拍 | 把打脸台词、下跪台词、「哥」这类**爽点武器**也按预算裁掉了（新稿只剩 3 句） |
| `4 八拍大纲` + `fuben_loop.py: 八拍表≥8行 / ≥6拍有推进·受阻·揭示·改变·停止·核对` | 防流水账 | 变成「每拍都要有客观状态变化」，模型就老老实实写票数、账本、药单：**状态一直在变，情绪一直不动** |
| `1.2 彩票题专用硬账：中奖只由官方结果核对、金额不漂移` | 防旧稿那类硬伤 | 没有配一条「兑现之后必须给一次爽点」，于是中奖 1040 元被当成「不能写大」的正确答案 |

**最关键的一句**：v3 的验收清单里有 7 项事实检查、6 项可读性检查，**0 项爽点检查**。模型不是写不出爽点，是没有被要求写。

## 八、以后怎么用

```bash
# 写新稿：先事实锁，再爽点表，最后正文
python3 scripts/fuben_run.py 作品/NN_xxx/        # design → facts → 爽点 → draft → review → lint
python3 scripts/fuben_hype.py 作品/NN_xxx/       # 只看爽点与节奏
```

三条纪律：

1. **没有爽点表的稿子不许写正文。** 表填不出来，说明选题还没想出好看的戏。
2. **事实锁管「不能错」，爽点锁管「不能停」。** 冲突时先改事件，不改事实：不能靠倍投制造爽点，但可以靠兑现、围观、借钱、打脸、账本对账制造爽点。
3. **八拍不是尺子。** 尺子是「22% 前有没有第一个爽点、峰值在不在 25–48%、有没有超过 30% 的情绪死区、结尾落在哪个数字或器物上」。
