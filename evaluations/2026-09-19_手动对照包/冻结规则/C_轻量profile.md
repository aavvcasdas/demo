# 人生副本口播 · 轻量创作 profile v11

适用：人生副本、剧本人生、第二人称人生体验类口播。**本文件替代旧 v10/R19 累加规则，不与旧骨架、旧提示词、通用网文契约叠加。**

## 先理解，再写

以本次用户要求为准：写谁、观众为什么想看、哪些剧情必须保留、交完整篇还是短版/切条。缺的信息只有会改变方向时才问；其余作合理假设并简短说明。用户要正文，就直接给正文，不先交一摞表。

在拆文库选与本题真正相近的原文，读原文而不只读拆解。通常一篇足够定位声音；需要比较另一种写法时再补一篇。已有材料足够就起稿；无法读取时如实说明，不伪造“已精读”。借处理方式，不搬人物、经历、原句；原文的转写错误和历史事实不是金标准。

默认第二人称「你」，贴近人物处境、可听懂的口语。签名式开场可用，但开头不一定先砸数字，人物也不必受辱、反杀、戒瘾或归零。用户给了不同人称、语气、结局时服从用户。

## 写一篇，而不是填一张表

先找到这篇值得体验的处境，顺着人物行动、得到的东西和随之而来的变化写下去。把重要的一刻展开，不重要的过程压过去。动作、对白、转述、心理、旁白、空白都可以用，判断依据是此处的效果，不是出现次数。

让开头给观众一个继续听的理由，让中间有值得看的发展，让结尾对前面的体验有所回应。情景喜剧可以一直赢，沉沦可以没有反杀，日常可以安静收束；不把它们改成同一条情绪曲线。

只在确有需要时参考 [可选创作抓手](人生副本_通用骨架.md)。不要默认加载通用短篇的付费点、8千至2万字、十二列表格、五段结构或去味清零表。

## 只守真正的边界

- 用户给定的事实、人物关系和不可改剧情优先。现实制度、价格、年份、来源有疑问就查与本篇有关的项；不强制搜索几次、凑几个 URL，也不强迫把搜到的数字都塞进正文。
- 分清角色误信、虚构推演和现实事实。没有查到的不能写成“官方已证实”。使用素材需尊重授权与隐私，不把真实网友经历冒充本人经历。
- 数量、时间、钱账确需精确时算清楚。同一个对象前后不能无缘无故变；倒叙、回忆和不同对象的数字不要求排成单调序列。
- 保留账号已明确的品牌/广告约定；品牌候选需结合语境确认，不把「小米辣」等同形词机械删除。
- 用户明确的时长是交付目标；字数/语速只能估时，不能声称已经配音、听完或实测过。

**撤销的通用配额**：八拍、情绪峰值位置、谷底分数、情绪点密度、首大事件百分比、场景行数、对白上限/下限、内心句数、每若干行感官词、呼应对数、数字预算、统一花钱比例与加注剧情。统计值可以描述稿子，不能反过来规定故事。

## 一次有针对性的复核

写完先完整读一遍，找最影响理解或体验的问题：观众是否知道眼下在发生什么；关键变化是否成立；最好的一刻有没有写出来；是否反复解释已经明白的东西。提出问题要指到具体段落与影响，别只说“AI味”“不够爽”。保留有效的原句和节奏。

能运行工具时：

```bash
python3 scripts/fuben_run.py 作品/NN_主题/ --profile full
# 短版与切条必须检查各自的正文文件，不沿用长稿结果
python3 scripts/fuben_run.py 作品/NN_主题/正文_3分钟版.md --profile short
```

`BLOCK` 修明确错误；`REVIEW` 核实上下文，可有理由保留；`NOTE` 是描述或未验证；`ERROR` 表示工具没成功，不算通过。只修本轮最重要且有证据的问题，避免“写到所有风格分归零”的无限循环。两轮仍是审美争议时展示分歧给作者，不自行重写整篇。

只交稿不等于授权制作或发布。用户要审稿时转 `fuben-review`；要制作时才做配音、字幕、成片检查；要发布时才做 `fuben_release.py` 证据验收。单个 Agent 自检要写明 solo，不把三个审查角度冒充三个独立审核者。
