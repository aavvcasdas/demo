# 人生副本 · 从 GitHub Agent 迁移的创作方法

这是主流程及子 Agent 的执行分工，不是给作者新增表格。创作目标沿用 [主profile](人生副本实录.md)。来源与适配位置见 [借鉴说明](../../../../docs/短视频Agent借鉴.md)。只加载本次负责的阶段；研究/改造 Agent 的任务到方法落地为止，不自动写样稿。

## 1. 主控先选能成立的开场，不直接押第一个想法

借鉴 writing-loop 的设计候选竞争，但只做轻量切口比较，不生成多个完整稿，也不启动其工单系统。

- 新题尚无明确开头时，内部比较两个**驱动力不同**的短开场，例如观众先知真相等人露馅，或观众只见反常结果等解释。不是同一意思换两个形容词。用户已定开头时不凑候选。
- 每个切口接一个“往下能发生的关键变化”：观众究竟在等什么，靠哪场行动兑现。只有噱头、接不上正文的切口淘汰；不是挑措辞最吓人的。
- 从参考原文提炼“怎样蓄期待、怎样兑现”的机制，不只提炼句长和词汇。先想清关键兑现，再把观众事后能看懂的线索放进前文；只有设定里知道、不在正文出现的信息不能算伏笔。

确定后，把本题事实、选中的切口、主角要争取的事、核心兑现及必要线索交给主笔；有对标时再传一段与本题相近、能看到蓄势到兑现的原文及其借用机制，不只传“参考这个风格”，也不塞整库分析。用一小段内部交接即可，不要求作者填卡或审批。仍没有值得追的事件，就重选切口，别先写长篇再用审稿救。

## 2. 主笔把爽点写成连续发生的戏

由 `narrative-writer` 或主会话完成。借鉴 drama-skills 的场景策略与反应后果：

- 在关键场面里写人物怎样争取、遭到什么有效阻力、为什么换招、哪一步改变局面。别用反复质问/否认拖长，也别把最关键的反击压成一句“后来你解决了”。这不是要求每段都有反派。
- 开场制造的压力尽快产生行动。背景在行动需要时补；小兑现可以释放一部分情绪，同时让新的选择或后果牵引下文。完整口播要在本篇偿还核心期待，不复制付费短剧的跨集吊胃口。
- 明牌时，让观众期待对手何时认清局面；暗牌时，让异常细节累积到揭示。不要为了惊讶隐去理解眼下行动所必需的信息。
- **侧面是主角行动留下的影响。** 对手改条件、旁人改变站位/称呼/选择、某件东西换了持有人，都能表现话语权变化。单写脸白、震惊、沉默不自动构成爽点：他原本能做什么，现在为什么不能再做？
- **不要让配角替主角爽。** 配角可以施压、作见证、付出代价或助攻，但若最难的一步全靠旁人说漂亮话、送证据、无条件帮忙，主角的反击就被拿走了。保留主角自己的策略与选择。

只交所需正文。候选淘汰理由、素材研究和编排术语不混进口播。

## 3. 审读先指出失去追看欲的位置，再决定退到哪一步

可调用新上下文的 `story-architect` 做创作审读；只给当前正文、brief和必要事实，不给作者自评、旧通过报告或“这里很爽”的解释。没有独立调用能力就由主会话自检并标 solo，不伪装多人意见。

让审读者回答：开场使我等什么？哪一段开始不再推进？哪个兑现没有被演出来？侧面反应究竟改变了什么？引用实际文字与前后行动，不能靠规则命中或总分判好看。

借鉴 short_drama_agent 的分层返工，但不用它的机械密度评分：

| 创作问题 | 主控交回哪里 | 改什么 |
|---|---|---|
| 切口平、欲望/阻力不成立、钩子无处兑现 | 主控／`story-architect` 重构 | 换入场与事件组织，重新连起承诺和兑现；不只换第一句 |
| 主线成立，但反击跳过、伏笔没落正文、侧面成捧哏 | `narrative-writer` 重写关键场 | 补人物主动选择、有效阻力、线索和兑现后的局面变化 |
| 戏已经成立，只是啰嗦、声线或局部衔接不顺 | `narrative-writer` 局部修 | 保留有效剧情和力度，不退回重写全篇 |

审读返回“具体原句＋损失＋返工层级＋修订目标”；不擅自代写整篇。改完再由审读看问题是否解决且主线仍成立，不凭写手回复“已修改”通过。审读没执行或没有实质回复就标未完成，不默认放行。沿用 `fuben-review` 的创作结论，不另造文学分数或字数门禁。

## 4. 只派需要的角色

`character-designer` 只在人物动机、台词博弈或侧面反应需要补强时参加：检查各人维护的利益，反应为什么改变下一动作，是否全成了给主角鼓掌的工具人。不必每篇都调用。

主控负责委派和返工，子 Agent 不递归拉团队。默认一轮成稿、一轮创作审读，必要时定点返工；方向仍有争议就说明争议，不循环刷“通过”。这些是创作分工，不声称已产生真实观众反馈。

原项目的自动提交、跨集票据、固定台词/伏笔配额、缺模型返回固定剧情等做法不引入。本仓普通小说流程、事实底线和发布授权保持各自边界。
