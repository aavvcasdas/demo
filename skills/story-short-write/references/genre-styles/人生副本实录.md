# 人生副本实录 · v3（2026-09-17）

> 这份包服务于抖音「今天体验的人生副本是……」的第二人称旁白稿。它不是把八拍、短行和拆书手法叠成一套模板，而是先把**事实、人物、物件、时间和状态**锁住，再用最少的形式让普通观众一遍读懂。
>
> v2 失败的根因已经确认：模型把「沉沦型」里的金额升级、系统拟人和反杀名场面泛化到不适用的题材；旧门禁却只检查行数、关键词和呼应，没检查玩法、日期、票数、因果与指代。v3 把事实锁和状态台账升为 BLOCK，把「社死/反杀」从全题材硬规定改成按题材选择。

---

## 0. 执行顺序与优先级

### 0.1 先参考，再生成，再比较

1. 先读取本包、`人生副本_通用骨架.md`、用户点名的「推送为1」拆文及 `拆文库` 的人生副本骨架；点名样本无法从仓库元数据确认时，必须报告「候选样本」而不是冒充已确认。
2. 把用户原案抽成一页**事实锁**，在隔离目录生成 `设定.md`、`小节大纲.md`、`正文.md`。不得在这一步先打开旧稿，更不得让旧稿的数字反向污染新稿。
3. 新稿完成 L0/L1 后，才读取旧稿及 67–72，逐行比较「模型执行失误」与「skill 没拦住的缺口」。
4. 发现可复现问题时，先修改本包和机械检查，再改正文；修改后至少跑 `fuben_run.py`。旧稿要保留为对比证据，重生成稿用独立目录。

### 0.2 冲突优先级

`用户明确硬事实 > 事实锁与官方规则 > 线性因果与可读性 > 选定拆文的机制 > 八拍/短行形式 > 文风装饰`。

拆文只能借**机制**，不能把供体的金额、年份、彩票玩法、人物关系或结局拷贝过来。`04` 的数字坠落、`21` 的成瘾回本、`01` 的线性物件编年可以分别借用；三者不能自动合成「先守号、后倍投」的新事实。

### 0.3 机械顺序

```text
L0 reference gate + 事实锁
→ L1 主线 / 因果状态台账 / 八拍大纲
→ 隔离生成
→ L2 facts（规则、数字、日期、票数、物件）
→ L2 draft（开头、对白、指代、行构造）
→ L2.5 review（每拍触发和状态变化）
→ L2.6 lint（普通话可读性）
→ fuben-review 人工三方审核
```

`python3 scripts/fuben_run.py 作品/NN_xxx/` 是机械串联器。任一 BLOCK 未过，不得用「对标像」「文风好」抵消。

## 1. L0 事实锁：写任何正文之前完成

### 1.1 事实锁的固定字段

`设定.md` 必须有 `## 事实锁`，每个项目至少写清：

| 字段 | 必须回答的问题 |
|---|---|
| 规则/玩法 | 这是什么制度、游戏或现实活动？一次如何判定？ |
| 频率/次数 | 每天、每周还是一次性？「每天一张」是每天一张**新票**还是重复使用旧票？ |
| 单价/金额 | 一次多少钱？金额是否允许改变？奖金/工资/欠款分别是什么？ |
| 对象/号码 | 人、物、地点、号码的明确称呼是什么？固定还是会变化？ |
| 结果/判定 | 谁在什么时候用什么证据确认结果？ |
| 日期/计数 | 起点、终点、年龄、天数、张数如何对账？ |
| 禁止越界 | 不得补写哪些预感、加倍、换号、身份、功能或制度？ |

每个数字必须有「单位 + 对象 + 时间」：`每张福彩3D单式票 / 2元 / 每天一张`，不能只写「2」「七年」「中奖」。

### 1.2 彩票题的专用硬账

如果主题是彩票，先锁**玩法名称**，再写正文。以福彩3D为例：

- 写「每天开奖一次、每天买一张**新出的2元单式票**」；不能写一张实体票连续使用。
- 写「始终购买同一组3位号码417」；不能从守号无解释地变成每天10元、五注、倍投或重仓。
- 福彩3D不能出现双色球的「红球、蓝球、六个红球」结构；若选择双色球，必须另建双色球事实锁，不能混称。
- 中奖发生在官方结果公布以后；由票面号码和官方公告核对。禁止「号码有感觉」「开奖前预感」「它认出了你」「快开了」「天选」等玄学因果。
- 「七年」必须选一种口径并写出算式。若起始日是 2019-09-17，不能把不含闰日的 2555 张和完整七年日期同时写成精确事实；应改成准确张数/日期，或明确写「按365天估算、约七年」。
- 金额账必须分开：购票成本、奖金、药费、工资不是同一列；`每天2元`不能在沉沦模板的压力下自动升级。

### 1.3 事实来源与可疑事实

规则、价格、税率、平台功能、制度动作需要来源；无法核实的写「虚构设定」并让正文避开精确断言。搜索只用来校准，不把网址、热搜话术或原型人物直接念进正文。

### 1.4 事实锁反事实清单

写前逐条回答并勾选：

```text
[ ] 玩法/制度只有一个名称，未混用相邻规则
[ ] 频率、单价、数量、金额全程不漂移
[ ] 起点、终点、年龄、天数/张数能算出来
[ ] 关键对象首次出现有身份、名称、单位和上下文
[ ] 结果由现实证据确认，不由预感确认
[ ] 供体拆文的数字和结局没有越权进入正文
```

任何一项不能勾选，L0 BLOCK。

## 2. L1 主线与台账：让剧情按因果推进

### 2.1 主线四句

`## 主线` 必须写：

1. **设定**：谁处在什么处境，反常点是什么。
2. **核心行动**：主角一直主动做的一个动作，而不是「经历了很多事」。
3. **悬念**：观众在等哪一个可回答的问题。
4. **一句话主线**：含结果，读完能复述。

每场景先问：「这场让核心行动推进、受阻、被核对还是停止？」都不是就删。规则/习惯题的主线可以是「每天买一张、保存、核对、停止」，不必硬安排一个会说话的反派。

### 2.2 因果/状态台账（硬门）

`## 因果/状态台账` 用表格记录每拍至少一行：

```text
时间/地点 | 触发（为什么现在发生） | 主角动作 | 物件/金额/数量 | 状态前 → 状态后 | 下一步
```

状态至少包含一项可见变化：钱、票数、物件位置、身体、关系、决定或信息差。只写「2019、2020、2021」是年表，不是因果链。

另外建立 `## 物件台账` 或 `## 人物台账`：每个关键对象写**首次出现 → 旁人再次碰到 → 后段回收**。对象第一次不能只用「他/她/这个东西/那件事」。

### 2.3 时间线

- 人生副本默认从第一件事线性推进：第一天 → 第一年 → 结果 → 第二天。
- 默认不使用深倒叙。若必须结果前置，前 4 行先明确「现在处于哪一天、结果是什么、接着回到哪一年」，闪回不超过 6 行，且要写「回到……」或等价的明确路标。
- 不用「七年后」后又突然回「小时候」；每次跨时都写触发和状态变化。
- 年份可以少，但不能让观众猜「这是谁、何时、为什么」。时间标签不是越少越好，清楚比压缩数量重要。

### 2.4 首屏普通话测试

前 5 行完成至少四件事：

```text
谁在做什么 / 关键物件是什么 / 时间或阶段是什么 / 读者要等什么结果
```

禁用未解释的「他、她、它、这个、那件事、那张票」。禁用把「命运的齿轮」「系统」「猎手」当成事实解释；若要用比喻，必须先把现实动作写清。

### 2.5 按题材选结构，不强行套反杀

| 题材 | 主动力 | 可用高潮 | 不得强行加入 |
|---|---|---|---|
| 规则/习惯/低剂量沉沦 | 重复动作与状态后果 | 客观核对、账本、停止/继续 | 倍投、天选、会说话的系统、社死审判 |
| 成瘾升级 | 频率/金额/身体/关系的可证明升级 | 账目崩断、旁人看见、戒断动作 | 无来源的金额跳级 |
| 性格缺陷/清算 | 主角日常小恶与对方一一归还 | 对质、报应、换手 | 抽象罪名、作者替观众宣布报应 |
| 现实编年 | 一个动作在不同阶段的后果 | 选择、关系或物件状态改变 | 为凑高潮制造反派 |

只有人物题且设定写了对手，才要求报应表/反杀现场；沉沦题可以用「结果核对 + 认知反转 + 停止」收束。

## 3. L2 正文规则：清楚、少对白、可朗读

### 3.1 第二人称与称呼

全篇使用「你」。每个新人物首次出现用身份或名字：`母亲`、`同事陈哲`、`彩票站老板娘`。同一场出现两个同性别人物时，后续每个换主语动作都重报名字/身份；「她/他」只能在上下文唯一时使用。每个物件首次出现写材质/用途/数量：`一张2元福彩3D单式票`、`装票的旧铁盒`。

### 3.2 对白预算

对白是功能件，不是换行节拍：

- 默认全篇直接对白不超过 8 个功能单位、总行数不超过 4%；一场最多一问一答。
- 只保留改变行动/关系/规则认知的句子：母亲一句边界、旁人一句事实、结尾一句换手。其余用动作或转述。
- 「说出、说完、听说、没有说话」不算对白；`你说 好 / 他说 嗯 / 她说 行` 这类空回应直接删。
- 不因为人物多就轮流让每个人发言。三人以上的场景优先写谁把什么物件放下、谁退开、谁没有接话。

### 3.3 短行只是声音节奏

一行一个动作、一个感官或一个信息；配音读起来顺即可。8–12 字和约300行是拆文样本的观察值，不是扩写指标；正文可在 220–420 个有效短行内完成。不得为了过行数重复年份、动作、对白、环境或身体反应。

### 3.4 每一段的最小闭环

```text
明确时间/地点
→ 触发
→ 主角连续动作
→ 物件或旁人反应
→ 状态改变
→ 下一步有理由
```

一个事件只完成一个信息就用一到三行；只有真的改变风险、关系、资源、信息或决定，才扩成场景。身体和环境要服务于状态，不按「每30行塞一句」硬填。

### 3.5 去模板和去 AI 味

可偶尔使用普通过渡，但不能固定复制「命运的齿轮」「这种事对你来说太正常」「空气开始变得稀薄」作为每篇标志。结构句必须紧跟具体动作，不能替代因果。旁白不宣判「你堕落了、这就是报应」，让账本、票、药单、座位、未接电话等证据完成判断。

## 4. 八拍大纲（路线图，不是八种强制戏剧）

每拍在大纲中写「时间/地点、事件、触发、状态前后、物件、对白（没有就写无）、拍尾动作」。推荐顺序：

| 拍 | 功能 |
|---|---|
| 一 | 题目、主角、核心动作和最小悬念；线性题直接进第一天 |
| 二 | 齿轮/第一次动作：为什么开始，第一次状态变化 |
| 三 | 重复形成习惯：阶段变化，不做流水年表 |
| 四 | 外部压力或现实代价：钱、身体、关系、规则 |
| 五 | 认知裂缝：旁人/结果/物件让旧解释站不住；无对手题不写假社死 |
| 六 | 台账对账：主角原来的解释与客观数字冲突 |
| 七 | 结果核对或人物对质：必须有证据和明确动作 |
| 八 | 新状态：停止、继续或接受，落在物件/动作上 |

八拍不是要求每拍都有反转。每拍必须产生可见状态变化；若两拍只是换年份而状态没变，应合并。

## 5. L2.5/L2.6/L2.7 验收

### L2.5 事实与逻辑

逐项问：

1. 玩法/制度、频率、单价、号码/对象是否与事实锁一致？
2. 所有日期、年龄、天数、票数、余额是否能算？
3. 结果是否在规则允许的时间由明确证据确认？
4. 每次时间跳转是否有触发和新状态？
5. 每个「他/她/这个」能否在两行内唯一指认？
6. 每一张票、账本、铁盒、药单等物件是否有前置和回收？
7. 对白删掉后，信息是否仍然清楚？保留的对白是否改变了动作？

### L2.6 普通观众可读性

`fuben_lint.py` 检查对白单位、空回应、同指代候选、陌生术语、首屏悬空物和模板过渡句。它是辅助，不允许通过机械替换姓名破坏自然语序。

### L2.7 三方审核

`fuben-review` 必须额外检查：拆文机制是否真正落地、外部事实是否适用、主线能否一句话复述、前后数字与日期是否守恒。发现同一问题在两篇以上重复，必须回写本包的「变更记录」和脚本，而不是只在正文润色。

## 6. 外部方法与本包的取舍

- `拆文库/01_无辣不欢的一生`：保留「一件小事贯穿多年、物件反复出现、具体感官」；不复制吃辣的奖赏结构。
- `拆文库/04_中10亿彩票的人生`、`21_大学生意外接触PG电子游戏`：只借数字/状态账和重复动作的沉沦机制；事实锁不允许把它们的倍投、网赌或中奖额度套入普通彩票题。
- 公开方法参考：知乎的赛道拆解强调第二人称、物证包和日常循环；GitHub `Mr-funny/hbg-life-simulation` 的工程说明强调先冻结原文、锁定人物锚点、把故事数据与分镜构建分离，再按真实语音时间做 QA；GitHub `1-SKILL/jiaoben` 强调把 hook、平台节奏和自检拆成结构化阶段。这里采纳「先锁数据、再拆分、最后验收」，不采纳未经验证的流量承诺。
