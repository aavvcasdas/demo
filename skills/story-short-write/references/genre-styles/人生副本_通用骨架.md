# 人生副本 · 通用骨架（拆文实测的可选形态 · v2，2026-09-17）

> 这份文件是从 `拆文库/01` 及其他人生副本样本抽出的观察，不是让模型照抄的硬模板。样本常见 2800–3500 字、约300个短行，但「300行」不能成为扩写目标；一篇事实清楚、状态变化完整的稿子，短一些也可以。

## 一、先画两张图，再写短行

### 1. 事实/对象图

```text
对象名称/身份 | 首次出现时间地点 | 数量/金额/规则 | 谁能看见 | 后段如何回收
```

示例：`一张新的2元福彩3D单式票 | 第一天彩票站 | 每天只一张、固定417 | 你/母亲/老板娘 | 官方结果核对后放回铁盒`。

### 2. 因果/状态图

```text
上一状态 → 触发（为什么现在） → 主角动作 → 客观结果 → 下一状态
```

没有箭头就不是剧情，只是年份和漂亮句子的并排。每次换年、换地点、换金额都要能回答「谁做了什么，所以现在变了什么」。

## 二、短行构造

| 类型 | 用途 | 示例形态 |
|---|---|---|
| 时间/地点行 | 给读者路标 | `2019年9月17日` / `第二天早晨` |
| 动作行 | 推动状态 | `你把2元放到柜台` |
| 物件行 | 让规则可见 | `出票机吐出一张新票` |
| 客观结果行 | 核对事实 | `官方结果不是417` |
| 身体/环境行 | 只在改变气压时使用 | `水壶开始响` |
| 极少对白行 | 改变动作或关系 | `每天一张就够了` |
| 数字行 | 对账，不炫技 | `第七年，购票成本约5114元` |

一行尽量只装一个动作或信息；长句在语义边界拆开。8–12字是常见音频节奏，不是每行必须达到的长度；不得用「你点头/你看了一眼/空气变稀薄」重复凑行。

## 三、线性八拍建议

| 拍 | 必答问题 | 典型状态变化 |
|---|---|---|
| 一 | 谁、现在做什么、观众等什么？ | 日常动作被命名 |
| 二 | 为什么第一次做？ | 第一个选择落地 |
| 三 | 重复如何变成习惯？ | 频率/票数/物件增加 |
| 四 | 什么现实压力逼近？ | 钱、身体、关系或规则变化 |
| 五 | 哪个证据让旧解释裂开？ | 旁人/账本/结果改变认知 |
| 六 | 客观数字怎么对账？ | 主角解释与账本冲突 |
| 七 | 结果由什么证据确认？ | 公告、票面、文件或当事人动作 |
| 八 | 结果之后状态是什么？ | 停止/继续/接受，落到一个动作 |

规则题、习惯题不强行插入「社死第五拍」或「反派末动作」。如果采用结果前置，必须在开头明写当前时间和回到哪一年；默认从第一天线性写。

## 四、单场景最小拍子

```text
时间地点明确
→ 触发动作
→ 主角连续动作
→ 物件/规则留下证据
→ 旁人或环境产生反应
→ 状态改变
→ 下一步有理由
```

只有真正改变风险、资源、信息、关系或决定的事件才扩成场景。对白默认一场一问一答以内；没有改变动作的对白删掉。人物超过一个时，每个新主语先用身份/名字，不让观众猜「他/她」是谁。

## 五、写作 Loop

```text
读取指定拆文和骨架
→ 事实锁
→ 对象台账 + 因果/状态台账
→ 八拍小节大纲（每拍有触发与拍尾动作）
→ 线性初稿
→ fuben_loop.py facts/draft/review
→ fuben_lint.py
→ 人工一遍读懂测试
```

门禁失败时只改对应事实、拍子或台账；不为满足行数补对白，不用模板金句掩盖时间线和数字矛盾。
