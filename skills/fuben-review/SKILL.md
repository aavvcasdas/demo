# fuben-review：人生副本三方审核 v3

你是审核员，不是作者。审核的第一目标是找出「前后事实不一致」和「观众看不下去（没有爽点、节奏太慢）」，不是把所有稿子压成同一种八拍。

**v3 新增**：事实全绿但零爽点的稿子＝失败稿。没有 `## 爽点表`、或爽点表锚点无法在正文定位、或密度/峰值位置不达标的，直接 `VERDICT: FIX`，不得因为「事实严谨」放行。

## 输入与硬门

输入是 `作品/NN_xxx/设定.md` + `正文.md`。设定缺 `## 事实锁`、`## 主线`、`## 因果/状态台账`、`## 爽点表`、`## 结构验收` 任一节，直接 `VERDICT: BLOCK`。规则/习惯题可以不写报应表，但必须有见证人/对照者，不能因此跳过事实、状态和爽点检查。

## Phase 0：机械预检

```bash
python3 scripts/fuben_run.py 作品/NN_xxx/
# v3.1 起 fuben_run 已内置 L1.6；单独复跑：
python3 scripts/fuben_setting_years.py 作品/NN_xxx/  # 设定散文层年份 vs 事实锁/正文
# 或逐项：
python3 scripts/fuben_loop.py design 作品/NN_xxx/设定.md
python3 scripts/fuben_loop.py facts 作品/NN_xxx/
python3 scripts/fuben_loop.py draft 作品/NN_xxx/
python3 scripts/fuben_loop.py review 作品/NN_xxx/
python3 scripts/fuben_hype.py 作品/NN_xxx/
python3 scripts/fuben_lint.py 作品/NN_xxx/ --fix-list
node skills/story-review/scripts/check-ai-patterns.js --check 作品/NN_xxx/正文.md
```

任一 `BAD` 或 blocking，报告至少 S2；事实、玩法、日期、票数、金额、人物知情面矛盾为 S1。

## Phase 1：事实账与前后逻辑

逐项从正文标行号，不凭印象：

1. **玩法唯一**：彩票题只能有一个玩法。福彩3D不得出现双色球红球/蓝球；「每天一张」必须是一张新票，不得突然每天10元、五注或倍投。
2. **数字守恒**：单位、金额、票数、次数、余额前后一致。把「每天2元」与「七年总额」写算式；精确日期遇闰日不能用约数冒充精确数。
3. **随机/结果边界**：中奖或结果必须在公布/文件/客观动作后确认。禁止把「有感觉、预感、天选」当因果。
4. **时间线闭环**：抄出所有事件年份、日期、阶段词，按出现顺序核对；倒退或无触发的跳年为 S1/S2。
5. **状态台账**：每拍必须存在触发、动作、物件/数字和状态前后；只有年月标题没有状态改变为 S2。
6. **知情面**：角色在第一次看见票、账本、消息、结果之前，不得依赖该信息行动。
7. **物件链**：关键物件必须有首次出现、旁人再次触碰、结尾回收；缺一段标 S2。
8. **人物指代**：每个「他/她/这个」在两行内能唯一指回身份；多名同性别人物同时出现就必须重报名字/身份。
9. **语义守恒（v3.1，算术过了不算过）**：钩子里的每一个计数（只有三张/没中过/一次没还），必须和正文**全部**「留/存/删/收/放回/带走」类动词逐一核对——物件被「留了」在哪（群相册≠手机相册）、被谁看见、结尾计数是否把它算进去。73 号「聚会那张你留了」被 12437−3 的算术对账放过，观众却一定在评论区抓到。凡正文出现与钩子计数**可能共域**的物件动作，必须写明容器（群相册/收藏夹/打印机），否则标 S2。
10. **设定卡散文层对账（v3.1）**：主线、节拍、台账、验收等散文句里的「物件+年份/金额」与事实锁逐项一致——58b 的 217/218、73 的「单反从 2015」都是散文层第二个出身。已脚本化：`scripts/fuben_setting_years.py`（进 fuben_run L1.6），但该工具只认「物件词邻域年份」，**人审仍需通读散文节一遍**，工具绿不代表语义绿（见第 9 条）。

## Phase 2：拆书库机制对照

### 2.1 人生副本骨架

读取 `skills/story-short-write/references/genre-styles/人生副本_通用骨架.md` v3 与 `人生副本实录.md` v4，逐节列：位置%、情绪值、正文行号、触发、状态变化、拍尾动作。**逐条核对爽点表**：锚点是否真的落在那句话上、声明位置与实际位置是否相差 ≤8%、第一个爽点是否 ≤22%、峰值（≥+5）是否落在 25%–48%、相邻爽点间距是否 ≤30%、结尾是否落在数字或器物判词上。不得只写「都是八拍所以像」，也不得只写「参考了 04」而没有机制落地行号。

### 2.2 供体手法

打开设定卡列出的 `拆文库/*/拆文报告.md`、`情节节点.md` 或 `写作手法.md`。每个供体回答：

- 借的是哪个机制，而不是哪个名词？
- 机制怎样改成当前人物、规则和数字？
- 正文哪一行落地？是否误把供体金额/反派/结局带入？

`04`/`21` 的数字坠落只能在事实锁允许成瘾升级时使用；规则题若写成倍投，标 S1。

### 2.3 物件/动作呼应

呼应表每一对都要有前置行和回收行。没有前置的「突然揭示」或没有改变状态的装饰回收，标 S3；事实矛盾仍优先于呼应数量。

## Phase 3：联网事实与同题方法

搜索 2–4 次，分别用于：

1. 规则、价格、开奖/制度动作和现实功能存在性；
2. 同题人生副本样本：只比较开头是否交代身份、物件、时间，和结尾是否落在可见动作；
3. 需要时核对日期、闰日、金额算式。

外部文章、GitHub skill 的流量承诺不是事实来源。搜索结果进报告，不把网址和热搜黑话塞进正文。

## Phase 4：普通观众 rubric

| 项目 | PASS 标准 | 失败级别 |
|---|---|---|
| 首屏 | 前5行知道谁、做什么、关键物件/规则、要等什么 | S1 |
| 线性与倒叙 | 默认第一天推进；倒叙有明确路标且不让人猜 | S1 |
| 主线 | 能一句话复述「你在做什么、等什么」 | S1 |
| 因果 | 每次换时间/地点/金额都有触发和状态变化 | S1 |
| 事实 | 玩法、频率、单位、号码、日期、数量可对账 | S1 |
| 对白 | 只保留改变动作的句子；旁白稿对白稀缺 | S2 |
| 称呼 | 人物、物件、事件首次有明确称呼 | S2 |
| 爽点 | 情绪节点 ≥4.0/千字、正向爽点 ≥2.0/千字、峰值 25%–48%、无 >30% 死区 | S1 |
| 节奏 | 前 22% 内出现第一个爽点；没有连续两节只换年份不换状态 | S1 |
| 高潮 | 按题材选择客观核对、账本对账、兑现围观、停止或人物对质；不许以「这题不该有高潮」为由留白 | S1 |
| 结尾 | 落在新状态和一个动作/物件，不是作者宣判 | S2 |

## 输出格式

写入 `作品/NN_xxx/审核报告.md`：

```text
=== 人生副本三方审核 v2 ===
Target: 作品/NN_xxx/
Search: N 次

## Phase 0 机械预检
(design/facts/draft/review/lint/AI-patterns)

## Phase 1 事实与逻辑
| severity | 行号 | 证据 | 问题 | 修复 |

## Phase 2 拆书机制对照
| 供体/样本 | 借用机制 | 正文行号 | 是否越权 |

## Phase 3 方法与搜索复核
(规则来源、同题钩子、结尾动作)

## Phase 4 Findings
- S1/S2/S3：category / location / evidence / issue / fix

## VERDICT: PASS | FIX(拍号列表) | BLOCK
```

任一 S1 → BLOCK；S2 两项以上 → FIX；修完必须重新跑机械门禁。规律性问题连续出现在两篇以上，回写 `人生副本实录.md` 变更记录和脚本，不只改某一篇。
