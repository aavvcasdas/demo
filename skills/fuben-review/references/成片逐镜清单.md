# 成片复核：只在制作/发布阶段使用

渲染成功、元数据正常，不代表内容正确。先取得实际文件；没有音视频时，相关项目记 `未验证`，不能靠正文估计填勾。此清单不反向规定写作节拍，也不要求先补设定/场面表。

## 对当前版本核实

- 正文、短版、配音、字幕、画面、标题/封面是否属于同一版；以哈希绑定，改稿/改片后重做受影响的审核。
- 听完整段音频：漏字、加字、数字/英文读法、断句、音量突变和意外静音。需要判断是否硌耳朵时真的听，不把“扫过文字”写成听感 QA。
- 字幕和声音是否表达同一意思；有意精简口头重复可以保留，但不能把否定、限定条件或关键数字删掉。核对文字出现的时机和可读性。
- 数字、日期、人名、机构名与当前正文/用户材料是否相符。新添的现实信息、版权/肖像/隐私风险单独核实；不以在全篇 grep 到一个词代替检查当前镜头。
- 道具、知情状态、人物关系与本场动作是否一致。区分制作失误与有意倒叙、错认、角色误信或复杂表情，不能看见“失眠的人在笑”就自动判错。

## 画面与交付

- 检查实际可见的问题：视线、手指、屏幕朝向、物件位置、字幕遮挡、黑帧与拼接缺段；不强制所有手机镜头都拍背面，也不强制所有画面文字不可读。
- 关键信息需要可读文字时，用可控制的字幕/合成层，逐字核对；不相信生图模型已经把中文、价格或合同写对。
- 明确检查账号已经规定的品牌/广告边界、素材授权和必要标识；封面、标题、评论引导不能承诺本条没有兑现的内容。
- 取得实际时长与音视频轨信息。`6.4字/秒`只是工具默认估值，不是本条实测；没有音频不说“前15秒已讲到”。若用户有明确时长上限，按实际成片验收。
- ffprobe 只能检查元数据，不会听感受或判断情节；工具缺失/失败记 ERROR，不能退回估时后说通过。

## 留最小证据

在审核报告记文件版本、具体时间码、问题/保留理由、复核方式与未验证项。单人检查标 solo，不声称独立多 Agent 会审。发布任务才填写 `.发布证据.json` 中的具名审核与媒体哈希；模板中的 UNVERIFIED 不能未经实际复核改成 APPROVED。

最终确认属于账号主。本地验收不保证平台审核通过，也不保证流量。
